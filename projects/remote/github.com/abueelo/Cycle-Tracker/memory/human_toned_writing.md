Any documentation (README, code comments) and user-facing UI copy should sound like a human wrote it quickly and directly — not AI-generated fluff, and not cheesy/forced-thematic marketing language (e.g. avoid leaning hard on a metaphor with puns like "pick up where you left the road").

**Why:** User called out the default create-next-app README as obviously unedited boilerplate, and separately said the site's copy was "cheesy" (e.g. "Log the miles. Watch yourself get there.", "Pick up where you left the road.", "Nothing logged here"). Rewrote README to be a terse, real project description, and cut the UI copy back to plain/functional phrasing (e.g. "Track your rides against a real route.", "Log in", "Page not found").

**How to apply:** When writing a README, code comments, or any UI text, default to short, plain, direct sentences that state what something does or is. Skip slogans, forced wordplay on a theme, and hype language. This is a general writing-style preference for this user, not project-specific — check new copy against it before finishing a UI-facing task.
